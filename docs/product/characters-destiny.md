# 角色与命运 / Characters and Destiny

## 中文

Mindspace 的角色既可以由用户自定义，也可以从 V7 命运抽签获得创作起点。抽签不是替用户决定关系或人格，而是提供可比较、可选择的角色灵感；最终进入聊天与长期使用的内容仍由用户确认。

### V7 命运抽签

V7 将角色灵感组织为 8 个方向、96 签。一次抽取会给出两组各 6 项候选，也就是 6+6 的 12 项选择。用户在这 12 项中选择喜欢的结果，再据此进入角色的确认、收藏或后续编辑；不喜欢的候选不会自动成为用户档案、关系事实或长期记忆。

### V2 角色卡

确认后的角色使用 V2 卡表达长期、可编辑的设定。V2 卡至少覆盖角色的自我认同与价值取向、主动性、语言与表达方式、常态场景、近期历史后的角色校准，以及按场景选用的示例。它用于定义“这个角色是谁、如何说话和行动”，不等同于模型某一轮临时编出的动作、服装或情节。

用户资料是全局所有；AI 档案、运行状态、关系、头像、共同经历和角色记忆都归属于各自的 `character_id`。角色之间不会互相覆盖档案或召回记忆。用户可编辑、归档、恢复、复制或导入受支持的角色资料；带有消息的会话不能改绑到另一角色，以保护对话连续性。

旧版、非 V2 的角色档案不再支持导入、自动升级或运行时兼容。请在导入前改用当前 V2 结构，并把旧档案作为独立备份保留；系统不会为了兼容旧档案而猜测、合并或改写当前角色资料。

## English

In Mindspace, a character can be created by the user or begin with a V7 destiny draw. A draw does not decide a relationship or personality for the user. It offers comparable character ideas that the user can choose from; anything that enters chat and long-term use still requires user confirmation.

### V7 destiny draws

V7 organizes character inspiration into 8 directions and 96 signs. One draw presents two groups of 6 candidates, for 12 choices in a 6+6 selection. The user chooses preferred results from those 12, then confirms, collects, or further edits the character. Unselected candidates do not automatically become profile data, relationship facts, or long-term memory.

### V2 character cards

A confirmed character uses a V2 card for durable, editable definition. A V2 card covers at least the character's selfhood and values, agency, voice and expression, baseline scenario, post-history calibration, and examples selected for the situation. It defines who the character is and how the character speaks and acts; it is not the same as a temporary action, outfit, or plot invented by the model in one turn.

User material is globally owned. AI profiles, runtime state, relationships, avatars, shared experiences, and character memories belong to their respective `character_id`. Characters neither overwrite one another's profiles nor retrieve one another's memories. Users can edit, archive, restore, copy, or import supported character material. A session that contains messages cannot be rebound to another character, which protects conversational continuity.

Older, non-V2 character archives are no longer supported for import, automatic upgrade, or runtime compatibility. Convert material to the current V2 structure before importing and keep old archives as separate backups. The product will not guess, merge, or rewrite current character material merely to accommodate an old archive.
