# 启动器首次引导与语音安装策略

适用版本：Mindspace 0.5.52。

## 目标

首次启动只把“能开始文字对话”作为阻塞条件。声音属于可选能力，不能让大模型下载、
WSL2、vLLM 或角色音色延迟 Core 和 LLM 的可用时间。

向导由四步组成：

1. 声音配置（可选）；
2. 基础环境（一键安装）；
3. 对话模型（API 配置与连接测试）；
4. 准备完成。

基础环境和 LLM 配置均完成后，首次引导即视为完成。声音可以仍在后台下载，或者完全不安装。

## 01：声音配置

选择卡片只保存偏好，不下载模型、不启动服务、不占用显存。

| 选择 | 面向用户的用途 | 最低建议 | 安装计划 |
| --- | --- | --- | --- |
| 暂不启用 | 只使用文字对话 | 无独立显卡要求 | 无 |
| GPT-SoVITS | 多套二次元角色音色 | 6–8 GB 显存 | 公共运行时 + 当前音色 |
| CosyVoice | 使用参考音频克隆声音 | 6–8 GB 显存 | 公共运行时 + CosyVoice 模型 |
| Qwen3-TTS | 高质量、具有活人感的预置声线 | 16 GB 显存、32 GB 内存、WSL2/vLLM | 受管 Qwen3 运行时 |

Qwen3 必须先通过 GPU、显存、内存、WSL2、vLLM 启动脚本和本地模型完整性预检。
任一条件不满足时，卡片只显示原因，不开放下载，避免普通用户误装高占用组件。

新用户选择本地声音后，在组件真正就绪前仍保持文字模式，不会误启动旧的本地 TTS。

## 02：基础环境

界面只提供一个主要操作“一键安装”。下载源默认使用“国内优先”，高级设置中可切换为
“仅官方源”。国内优先地址是低带宽控制入口：只返回 `302` 到 PowerShell、Git for Windows、
Astral uv 等权威上游，不在官网服务器中转或保存大型运行时。这样可以通过小型热更新调整
上游地址，同时避免占满官网带宽。

基础链按依赖顺序安装：

`PowerShell → MinGit → uv → Python → Core 环境 → 中文向量模型`

下载器保留 `.partial` 文件，支持 HTTP Range 续传；每个文件下载后执行尺寸、哈希和安装标记
校验。断网或关闭启动器后再次执行会复用已完成项目和断点文件，不从零开始。

Python 不能只用 `--version` 判断就绪。Launcher 会检查标准库文件，并实际导入
`encodings`、`ensurepip` 和 `venv`。旧版弱校验标记会在首次运行时自动升级：验证成功则
原地复用；验证失败则由 uv 对当前 Python 版本执行 `--reinstall`，不删除其他运行时、模型、
用户数据或下载缓存。

国内优先地址发生 DNS、连接或上游错误时，只尝试一次，随后自动切换官方地址；官方地址使用
有限重试，不会在两个来源间循环。界面显示当前实际域名和是否发生回退。Python 安装和 PyPI
依赖同步同样具有一次受限回退：Astral Python 镜像失败后改用官方入口，阿里云 PyPI 失败后
改用 PyPI 官方入口。

运行时映射的可复用 Nginx 配置位于
`deploy/nginx/mindspace-runtime-redirects.conf`。公开服务器只部署这份文本配置，不上传
PowerShell、MinGit、uv、Python、ASR、TTS 或模型文件。

基础环境和可选声音属于不同调度域：

- 基础环境优先完成；
- 基础环境完成后，用户已选声音进入独立后台队列；
- 声音失败只更新声音卡片与通知，不改变文字聊天可用状态；
- 同一时刻只安装一个声音计划，不能把三套 TTS 一起装入显存；
- 声音就绪后弹出一次提示，用户可立即重启声音服务，也可留到下次启动。

## 03：对话模型

启动器内置三个入口：

- DeepSeek：`https://api.deepseek.com`，默认 `deepseek-v4-flash`；
- SiliconFlow：`https://api.siliconflow.cn/v1`，默认
  `deepseek-ai/DeepSeek-V3.2`；
- 自定义 OpenAI 兼容接口。

远程接口必须填写 API Key；`localhost`、`127.0.0.1` 和 `::1` 的本地兼容端点允许空 Key。
“测试并保存”只发送一个最多两个 token 的连通性请求，并把 401、402、404、429 和超时转换为
可操作提示。API Key 不进入启动器日志、公开快照或诊断导出。

## 返回用户

当基础环境和 LLM 均通过真实状态检查后，启动器直接进入服务管理，不再重复弹出首次引导。
用户可以从维护区选择“重新配置”，手动返回向导修改声音或 LLM。

仅保存 `completedAt` 不能绕过检查：环境被移动、模型配置失效或远程 Key 被清空时，状态会按
真实条件重新计算。

## 三套 TTS 的 Prompt 与读取边界

| Provider | LLM 语音 Prompt | LLM 到 TTS | TTS 请求 |
| --- | --- | --- | --- |
| GPT-SoVITS | 只要求自然、可直接说出口的中文；禁止语气标签和状态说明 | `response.delta` 按自然语义边界进入队列 | 多段串行、边合成边播放 |
| CosyVoice | 与 GPT 相同，只做口语化，不传状态 | `response.delta` 按自然语义边界进入队列 | 多段串行、边合成边播放 |
| Qwen3-TTS | 开头允许一个隐藏 `[[voice:...]]`，正文仍必须是纯口语 | 标签在 Core 剥离，完整正文到达后一次提交 | 单轮一个 CustomVoice 请求，标签映射为 `instructions` |

Qwen3 的“非流式阅读”指一次 LLM 回复不拆成多次声学请求。底层同一个 HTTP 请求仍可在首批
PCM 生成后边传边播，以降低完成正文后的首声等待。GPT-SoVITS 和 CosyVoice 不接收
`voice_cue`，即使模型偶发输出旧标签，Core 也会清理而不会把状态文字读出来。

三种 Provider 都复用同一个取消域和串行播放队列。切换 Provider 时先停止旧引擎并释放显存，
再启动新引擎；失败则保留明确错误，不自动双开或隐式启动高占用 Qwen3。

## 代码位置

- `desktop/onboarding-policy.cjs`：完成条件、声音安装计划、LLM 预设；
- `desktop/main.cjs`：IPC、后台声音队列、API 测试、硬件预检和服务切换；
- `desktop/src/main.tsx`：四步向导与声音完成提示；
- `src/mindspace_graph/prompting.py`：按 Provider 组装语音输出协议；
- `src/mindspace_graph/nodes.py`：Qwen3 专属语气标签解析；
- `frontend/src/App.tsx`：GPT/Cosy 流式分段与 Qwen3 整轮单次提交。

## 不变的数据边界

本改造不迁移、不覆盖 `data`、人物卡、用户 JSON、RAG、ASR 模型或已有角色音色。启动器更新
只更新程序文件；可选声音下载写入独立模型和环境目录。
