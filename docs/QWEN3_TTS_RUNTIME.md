# Qwen3 实时语音运行时

Mindspace 0.5.46 将 Qwen3-TTS 作为可选、本机常驻的 `qwen3-vllm` Provider。桌面端仍调用
`/api/v1/audio/tts/stream`，Core 再以长连接转发到本机 `http://127.0.0.1:8091/v1/audio/speech`，
返回原始 PCM。因此前端 Worklet、语音分段、取消和重试协议不需要改变。

## 安装与启动

Launcher 先异步检查受管 WSL2 发行版 `MindspaceVLLM`、WSL 内 NVIDIA GPU、至少 14 GB 显存、
端口和本地模型启动脚本。任一条件不满足时，组件显示具体原因并禁用，不会提供下载入口。该组件仅
接入用户已准备好的本地 Qwen3/vLLM 环境：不会自行安装 WSL2、vLLM 或下载模型，也不会迁移或覆盖
`data`、ASR、GPT-SoVITS、人物 JSON 或角色卡。

安装器本身是轻量的，不携带或解压基础 Python/PowerShell 运行时；首次打开 Launcher 时才会以可见
进度部署基础环境。这个步骤同样不会下载或启动 Qwen3。

服务端使用稳定的 eager 配置，避免 RTX 50 系列在 CUDA Graph / FlashInfer JIT 上的不确定性。
首次启动会进行一次不可见 warm-up，可能较慢；Launcher 仅在服务健康后把 Qwen 标为可用，
主界面、文字聊天和 ASR 不会等待这一步。

## 资源与切换

Qwen3 CustomVoice 常驻约需要 10 GB 显存。它与 GPT-SoVITS 是互斥的手动选择：Launcher 只停止
自己启动的旧引擎，并等待其释放；超时或发现外部启动的旧服务时会阻止切换并给出关闭来源的提示。
Qwen 崩溃或未安装时仅 TTS 不可用；不会锁住语音识别、聊天页面或重新生成回复。

默认声线为 CustomVoice 的 `serena`。模型权重在推理时保持冻结；每轮固定 speaker、固定 seed，
并只建立一次完整声学上下文。`instructions` 只能描述语速、停顿、笑声、换气和情绪，不得描述
年龄、音高、声线或新的角色身份，避免在风格变化时重新塑造 speaker。设置页只显示服务实际
返回的九个预置声线，不伪造列表。

## 口语协议

实时语音轮只有一次正文模型调用。正文必须可直接说出口，不含括号、隐藏声线标签、舞台说明或
Markdown；面对面场景只作为对话语境，不把动作和外观改写成第一人称播报。思考、轻笑、叹息、
换气或轻哼需要听见时，
模型把它自然写成“嗯……”“呵……”“呼……”等真正能被合成的短发声和停顿，不再把不可听见的
标签交给 TTS 临场解释。普通轮按情境使用一处，亲密轮最多两处，避免机械堆叠。

自然口语由正文模型直接生成：通常三至五句、约七十至一百五十个中文字符，长短片段混合、
自然承接、允许有限犹豫或改口，并避免排比、总结式收束和字字落稳的书面台词。R18 模式允许
用直接、低俗或色情的口语表达角色自己的舒服、欲望、喘息、反馈与对用户表现的评价，但不朗读
动作说明。这样不会为了“更像人”再增加一次润色模型调用。

Core 固定使用 CustomVoice 的 Serena，并保持 HTTP `stream=true`。Qwen 不再抢跑首句；正文完成
格式清理和能力声明保护后，Core 立即发送 `response.ready`，前端把完整回复一次提交给 TTS。
这一事件早于角色审计、数据库持久化和 `run.completed`，所以不会为了整轮单次合成额外等待收尾链路。
`run.completed` 仅在 `response.ready` 丢失时兜底，同一回复最多提交一个声学请求。手动“朗读”同样
保持一次整段合成；PCM 到达后仍边接收边播放。由此消除跨段声线漂移、重复排队和段落接缝。
连接正文的“嗯、呵……”会与全文处于同一个声学上下文；整段全是填充词时才丢弃。
vLLM 的原始 PCM 流式接口要求 `speed=1.0`，所以产品速度设置通过 CustomVoice 的简短韵律指令
表达。正文出现“呵／哈”“呼／唔”“唉／哎”时，Core 分别选择一次轻笑、换气或叹息演绎；它只
影响本轮整体韵律，不改变 Serena speaker，也不改写屏幕正文。

诊断接口只暴露 Provider、健康、队列深度、首 PCM、完成耗时、预热状态和取消原因；不返回
文本、PCM、转写或密钥。
