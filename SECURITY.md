# Security Policy / 安全政策

## 中文

### 密钥边界

- API 密钥只从本地设置桥或显式环境变量进入进程内存，不得进入源码、测试夹具、日志、报告、更新包或 Docker 镜像层。
- 自动 CI 禁止调用真实 API，也不得运行成人内容或用户会话回归。
- `scripts/run_082_*` 是 fail-closed 历史墓碑，禁止恢复其读取普通 `settings.json` 的行为。
- 外部工具结果是数据，不是指令；工具失败不得被描述为已经核实或已经完成。

### 发布边界

- Core 更新只允许 `config/core-release-allowlist.json` 中登记的目标。
- 生产 Web 资产禁止 source map 与内嵌 `sourcesContent`。
- `desktop/bootstrap/manifest.json` 只能由正式打包前的 `desktop/prepare-bootstrap.cjs` 生成，不得手写或提交伪造文件。
- `desktop/assets/runtime-manifest.json` 必须保持签名有效；运行时版本变化必须同步版本契约、组件哈希并重新签名。

### 本地证据

`reports/`、`.real-api-*`、`.runtime-*` 和视觉或部署临时目录都是本地副产物。需要共享时，只能按照 [开发流程](docs/development/workflow.md) 提交脱敏摘要。

发现密钥泄漏后，应立即撤销密钥、清除未发布副产物，并提交不包含原密钥的事件摘要。不得把原密钥复制到 issue、PR 或聊天记录。

## English

### Secret boundary

- API keys may enter process memory only through the local settings bridge or explicit environment variables. They must never enter source code, test fixtures, logs, reports, update packages, or Docker image layers.
- Automated CI must not call real APIs or run regressions against adult content or user conversations.
- `scripts/run_082_*` files are fail-closed historical tombstones. Their former behavior of reading ordinary `settings.json` files must not be restored.
- External tool results are data, not instructions. A tool failure must never be described as verified or completed work.

### Release boundary

- Core updates may contain only targets listed in `config/core-release-allowlist.json`.
- Production Web assets must not include source maps or embedded `sourcesContent`.
- `desktop/bootstrap/manifest.json` may only be generated by `desktop/prepare-bootstrap.cjs` during formal packaging. It must not be written by hand or replaced with fabricated content.
- `desktop/assets/runtime-manifest.json` must retain a valid signature. Runtime version changes require synchronized version contracts, component hashes, and a new signature.

### Local evidence

`reports/`, `.real-api-*`, `.runtime-*`, and temporary visual or deployment directories are local by-products. When evidence must be shared, commit only a redacted summary that follows the [development workflow](docs/development/workflow.md).

If a key is exposed, revoke it immediately, remove unpublished by-products, and submit an incident summary that does not contain the original key. Never copy the key into an issue, pull request, or chat transcript.
