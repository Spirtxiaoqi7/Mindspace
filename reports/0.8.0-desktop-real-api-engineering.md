## 5. 真实测试后修复

### 5.1 DeepSeek 后台结构化请求

`OpenAICompatibleLanguageModel.compact()` 和 `audit_role()` 改为使用 `_private_completion()`：

- 显式关闭思考模式
- 优先请求 JSON object
- 保留 400/404/422 的 OpenAI 兼容字段降级
- 保留 usage 采集

### 5.2 压缩输出边界

压缩提示新增服务器约束：

- summary 120 个中文字符以内
- scene 单字段 30 字以内
- events 最多 6 项
- open threads、commitments、relationship deltas 各最多 4 项
- confirmed facts 最多 6 项
- temporary cues 最多 3 项
- 单条 text 最多 80 个中文字符

### 5.3 成人纠偏隔离

`previous_turn_correction` 只在上一助手消息与当前请求的 `adult_mode` 相同时继承。成人开启轮产生的纠偏不再进入关闭成人模式后的普通提示词。

### 5.4 压缩证据角色过滤

共同事件、事实、关系变化、未完话题和临时用户线索必须至少引用一条用户消息；角色自己的承诺必须引用助手消息。该规则能拦截仅由助手输出自证的共同记忆，但不能证明“用户消息与摘要文本在语义上真的一致”，所以还不是最终 grounding 方案。

## 7. 未解决缺陷

### P1：共同记忆缺少语义级证据核验

最终复测中仍出现：

- 第 13 轮编造用户曾答应借书
- 第 14 轮把假设性的吃醋问题改写成现实中的熟人关系
- 第 16 轮编造“昨晚设定暗号”的时间

摘要器随后把“借书未果”等内容写入连续性包。这说明仅验证 evidence ID 和消息角色不够。下一版需要为每个 claim 保存 `subject/type/evidence_quote/message_id`，校验引用片段确实存在，并对“摘要是否被原文蕴含”做轻量 NLI 或二次验证。涉及用户事实和共同经历时，未通过验证的内容只能进入低置信临时线索，不能进入 confirmed facts、relationship deltas 或 continuity overview。

### P1：成人推进状态机仍会退回预告

第 18 轮成人回复只停在靠近、拉手和“换我来”，被当前质量检测标记为：

- `r18_missing_sexual_action`
- `r18_foreplay_loop`

当前正则仍可能把“想要、将要、询问”误判成已发生。需要把成人状态改成服务器维护的显式阶段，并增加时态/行为发生检测。

### P2：回复骨架重复

20 轮全部使用括号动作开场。下一版需要保存最近开场签名和常用道具，按“直接台词、判断、提问、动作、场景推进、角色自主话题”等骨架轮换；质量检测应加入开场相似度与道具重复率，而不仅是整段文本相似度。

### P2：能力真实性提示侵入角色正文

第 2 轮出现“这轮没有实际联网查询”的角色外声明。需要把能力真实性守卫的提示搬到 UI 状态、来源栏或角色外 transport metadata，避免直接改写沉浸式正文。
